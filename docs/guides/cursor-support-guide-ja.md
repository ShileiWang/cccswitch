# CC Switch で Cursor を管理する

CC Switch は Cursor のプロバイダーを直接管理できるようになりました。複数追加してワンクリックで切り替え、Skills とプロンプトファイルも同期されます。ここでは Cursor の設定場所、切り替え時に何が起きるか、Claude Code や Codex との違いを説明します。

## Cursor はどう管理されるか

Cursor で有効になるプロバイダーは常に 1 つです。CC Switch は「有効リスト」を持たず、有効なプロバイダー設定を上書きします。

| 内容 | 場所 |
| --- | --- |
| 有効なプロバイダー | `~/.cursor/cli-config.json` |
| MCP | `~/.cursor/mcp.json` |
| Skills | `~/.cursor/skills` |
| プロンプトファイル | `~/.cursor/rules` |
| ログイン情報 | Windows: `%APPDATA%\Cursor\auth.json` / macOS・Linux: 設定ディレクトリ内 |

CC Switch が `cli-config.json` に書き込む部分は次の形です。

```json
{
  "model": "モデル名",
  "env": {
    "CURSOR_API_KEY": "sk-...",
    "CURSOR_BASE_URL": "https://..."
  }
}
```

ファイル内の他の内容はそのまま残り、これらのキーだけが上書きされます。

## プロバイダーの追加と切り替え

1. サイドバーで **Cursor** を選び、プロバイダーページで追加します。
2. API キー、ベース URL、モデル名を入力します。プリセットがあるプロバイダーはそのまま使えます。
3. 保存後、カードの **有効化** をクリックすると `cli-config.json` に書き込まれ、Cursor の次のリクエストがそのプロバイダーへ送られます。
4. 別のプロバイダーに切り替えるには、別のカードを有効化します。上書き方式なので、先に無効化する必要はありません。

フォームの変更は保存するとすぐ `cli-config.json` に反映され、Cursor で新しい会話を開けば使われます。開いている会話は再起動するまで以前の接続のままです。

## 設定ディレクトリの変更

既定値は `~/.cursor`（macOS / Linux）です。別の場所を使っている場合や、複数の構成を分けたい場合:

- **設定 → Cursor 設定ディレクトリ** にパスを入力する、または
- 環境変数 `CURSOR_CONFIG_DIR` を設定する

設定の値が優先されます。変更すると `cli-config.json`、`mcp.json`、`skills`、`rules` はすべて新しいディレクトリになります。

## Skills・プロンプトファイル・MCP

- **Skills** は `~/.cursor/skills` にインストールされ、Cursor が直接読みます。
- **プロンプトファイル** は `~/.cursor/rules`（Cursor が `AGENTS.md` を読むディレクトリと同じ）に書き込まれます。
- **MCP** は `~/.cursor/mcp.json` に直接書き込まれ、統合 MCP パネルには **含まれません**。Cursor はこのローカルファイルだけを読み、グローバルな MCP 同期には参加しないため、パネルに Cursor の列はありません。

## ローカルルーティングについて

Cursor は CC Switch のローカルルーティングサービスを **経由しません**。ルーティングモードもありません。

- 設定 → ローカルルーティングの **グローバルルーティング** スイッチは Claude Code、Codex、Gemini、Grok Build、Claude Desktop のみが対象です。
- Cursor のページにルーティングタブはなく、プロキシにも接続できません。

つまり Cursor は有効化したプロバイダーへ直接接続します。リクエストはローカルプロキシを通らず、使用量にもリクエスト単位の明細は表示されません。

## よくある質問

**切り替えても Cursor のモデルが変わらない。** 会話を終了して新しく開始してください。`cli-config.json` は更新済みで、Cursor は会話開始時に読み込みます。

**Cursor 公式のログインを併用できる?** できます。API キーを空にすれば認証情報は Cursor 自身の `auth.json` に残ります。CC Switch が有効化するのは自分で追加したプロバイダーで、互いに上書きしません。

**設定ディレクトリを変更すると以前のプロバイダーは消える?** 消えません。元のディレクトリに残るので、戻せば表示されます。
