# CC Switch v4.0.20 + Cursor

本版本新增 **Cursor** 应用支持，并加入 **全局路由** 总开关。Cursor 有自己的供应商、Skills 和提示词管理，配置写在 `~/.cursor`，切换即覆盖当前生效的供应商；设置 → 本地路由里新增一个总开关，可以把所有支持路由的应用一起带入路由模式，关掉则一起退回直连，各应用仍可单独调整。

---

## 新增

### Cursor

Cursor 现在和其它应用一样由 CC Switch 管理：可以添加供应商、切换供应商，同步 Skills 和提示词。

- **配置目录。** 默认 `~/.cursor`（macOS / Linux）；Windows 的登录凭据在 `%APPDATA%\Cursor\auth.json`。可以在设置 → Cursor 配置目录里改成别的目录，也可以用 `CURSOR_CONFIG_DIR` 环境变量覆盖。
- **供应商写入 `cli-config.json`。** 落点按 `{ "model": <名称>, "env": { "CURSOR_API_KEY", "CURSOR_BASE_URL" } }` 写。Cursor 一次只生效一家供应商，所以切换是覆盖而不是叠加，文件里其它内容原样保留。
- **Skills 与提示词。** Skills 装进 `~/.cursor/skills`，提示词写进 `~/.cursor/rules`（与 Cursor 自己读 `AGENTS.md` 的目录相同）。
- **MCP 只在本地。** `~/.cursor/mcp.json` 直接写本地文件，**不纳入**统一 MCP 面板：Cursor 只读这一份文件，不参与全局 MCP 同步。
- **Cursor 不经过本地路由。** 它没有路由模式，因此不参与全局路由，也不会接上本地路由服务。

### 全局路由

设置 → 本地路由新增一个总开关：**所有支持路由的应用一起进入路由**。

- 打开时，所有支持路由的应用（Claude Code、Codex、Gemini、Grok Build、Claude Desktop）按各自上次使用的路由目标进入路由模式，并启动路由服务。已经接上代理的应用不动，处于聚合模式的也保持聚合模式。
- 关闭时会先确认，然后把所有应用退回直连并停止服务。路由目标、队列和聚合名单都保留。
- 这一行显示当前接上了几个应用，例如「5 个应用中 2 个已接管」。各应用自己的页面里仍然可以单独切换。
- 单个应用失败不影响其它应用：结果会说明哪几个进了路由，没进的带上原因。
