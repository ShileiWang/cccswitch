# CC Switch v4.0.20 + Cursor

This release adds **Cursor** as a managed app and a **global routing** switch. Cursor gets its own provider, MCP skills and prompt-file management in `~/.cursor`, switching by overwriting the live provider config. In Settings → local routing, one switch now puts every app that supports routing into routing mode at once and starts the service; turning it off takes them all back to direct. Each app still keeps its own per-app override.

---

## Added

### Cursor

Cursor is now managed alongside the other apps: add providers, switch between them, and sync Skills and prompt files.

- **Config directory.** Defaults to `~/.cursor` (macOS/Linux); Windows reads the auth file from `%APPDATA%\Cursor\auth.json`. The directory can be overridden in Settings → Cursor configuration directory, or with the `CURSOR_CONFIG_DIR` environment variable.
- **Providers write `cli-config.json`.** A provider is written as `{ "model": <name>, "env": { "CURSOR_API_KEY", "CURSOR_BASE_URL" } }`. Cursor keeps one live provider at a time, so switching is an overwrite rather than an additive list. Existing keys in the file are preserved.
- **Skills and prompt files.** Skills are installed into `~/.cursor/skills`, prompt files into `~/.cursor/rules` (the same directory Cursor uses for `AGENTS.md`).
- **MCP stays local.** `~/.cursor/mcp.json` is written directly and is *not* part of the unified MCP panel, because Cursor only reads this one file and does not take part in global MCP sync.
- **Cursor is not routed through the local proxy.** It has no routing mode, so it is excluded from global routing and from the local routing service.

### Global routing

Settings → local routing now has one master switch, **Route every supported app at once**.

- Turning it on puts every app that supports routing (Claude Code, Codex, Gemini, Grok Build, Claude Desktop) into routing mode, each with the target it used last, and starts the routing service. Apps that are already connected are left alone, including those in Aggregation mode.
- Turning it off asks for confirmation and takes every app back to direct, then stops the service. Route targets, queues and aggregation lists are kept.
- The row shows how many of the apps are currently connected, e.g. "2 of 5 apps connected". Each app's own page still switches it individually.
- One app failing does not block the others: the result names the apps that entered routing and, for the rest, the reason.
