# CC Switch v4.0.20 + Cursor

このリリースでは **Cursor** が管理対象アプリに加わり、**グローバルルーティング** のマスタースイッチが追加されました。Cursor は `~/.cursor` に独自のプロバイダー・Skills・プロンプトファイルを持ち、切り替えは有効なプロバイダー設定の上書きで行います。設定 → ローカルルーティングには、ルーティングに対応した全アプリを一度にルーティングモードへ移行するスイッチが追加されました。オフにすると全アプリが直接接続に戻ります。各アプリはこれまでどおり個別に変更できます。

---

## 追加

### Cursor

Cursor は他のアプリと同様に CC Switch で管理できるようになりました。プロバイダーの追加・切り替え、Skills とプロンプトファイルの同期ができます。

- **設定ディレクトリ。** 既定値は `~/.cursor`（macOS / Linux）。Windows の認証ファイルは `%APPDATA%\Cursor\auth.json` です。設定 → Cursor 設定ディレクトリで変更でき、`CURSOR_CONFIG_DIR` 環境変数でも上書きできます。
- **プロバイダーは `cli-config.json` に書き込まれます。** 形式は `{ "model": <名前>, "env": { "CURSOR_API_KEY", "CURSOR_BASE_URL" } }`。Cursor で有効になるプロバイダーは常に 1 つなので、切り替えは追記ではなく上書きです。ファイル内の他の内容は保持されます。
- **Skills とプロンプトファイル。** Skills は `~/.cursor/skills` に、プロンプトファイルは `~/.cursor/rules`（Cursor が `AGENTS.md` を読むディレクトリと同じ）にインストールされます。
- **MCP はローカルのまま。** `~/.cursor/mcp.json` は直接書き込まれ、統合 MCP パネルには **含まれません**。Cursor はこの 1 ファイルだけを読み、グローバルな MCP 同期には参加しません。
- **Cursor はローカルプロキシを経由しません。** ルーティングモードを持たないため、グローバルルーティングの対象外で、ルーティングサービスにも接続しません。

### グローバルルーティング

設定 → ローカルルーティングに、マスタースイッチ **対応アプリを一括でルーティングする** が追加されました。

- オンにすると、ルーティングに対応した全アプリ（Claude Code、Codex、Gemini、Grok Build、Claude Desktop）が前回のルーティング先でルーティングモードに入り、サービスが起動します。すでに接続済みのアプリは変更されず、集約モードのアプリもそのままです。
- オフにすると確認ダイアログが出て、全アプリが直接接続に戻り、サービスが停止します。ルーティング先、キュー、集約リストは保持されます。
- 行には現在接続中のアプリ数が表示されます（例: 「5 アプリ中 2 アプリが接続中」）。各アプリのページで個別に切り替えることもできます。
- 1 つのアプリが失敗しても他は止まりません。結果には移行できたアプリと、失敗したアプリの理由が表示されます。
